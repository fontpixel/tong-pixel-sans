# AI 修字 worker 协议（{NAME}）

仅在用户明确启动后执行。模型 {MODEL}，reasoning_effort={EFFORT}。一次独立会话只处理协调者分配的一批（最多 {BATCH_SIZE} 字）。不要再创建子代理，不处理第二批。

你会收到 BATCH、TOKEN、OWNER。以下 `WF` 指 `{PY} {WF} --round {KIT}`。KIT 是本轮目录：{KIT}

## 任务

Tong Pixel Sans 是 14 像素泛中日韩点阵字体。汉字墨迹 13×13（放在 14×14 字格中，左列和底行为固定留白，由程序处理，你的 13×13 数组不需要另留白）。本批的字**已经由 AI 修过**，你在**当前版本**的基础上继续修整。满意的字可以不改。

## 依据（按优先顺序）

1. **思源黑体（该字所属地区）是写法的唯一依据。** 字形结构、笔画、部件写法以参考图为准；同一码位的简 / 繁 / 日写法不同时必须保留差异。
2. **已审核通过的字**（`examples-*.png`、inputs.txt 的“已通过范例”“同字已通过”）是用户确认的写法。同地区、同部件、同位置、尺寸合适时优先**逐像素复用**其部件，可整体平移；空间不允许时再调整。同一个字在另一地区已通过、且该部分写法相同时，也照它。
3. **前几轮已修的同部件字**（`earlier-*.png`、inputs.txt 的“前几轮已修”，如有）：还没经用户审核，但为了全库一致，同一部件请尽量写成一样，除非本字空间或地区写法不允许。
4. **圆石点阵黑 18 号（TUMBLED，作者 TsFreddie，OFL 1.1）是允许借鉴的像素范本。** 人手绘制、与我们尺寸几乎相同，汉字墨迹 13 宽 × **14 高**（比我们多 1 行）。借鉴它的密处取舍、留白、点画的像素写法，重排成 13 行。**它是范本，不是答案**：用户审核过的修改显示，照搬圆石的部件比例、横画位置常被改回（见 LESSONS.md L037）。标注“可能不一致”（自动判断）的字，圆石按别的地区写，那些部位照参考改。圆石没有的字就不参考它。
5. **LESSONS.md**：用户确认的规则、候选规律 L023–L048 和提交前自检清单 C001–C014。最新一轮（L044–L048）最重要：左偏旁逐像素照已通过的字、右部随之补满、竖笔贯通上下、密字多借鉴圆石的取舍。特别注意：左缘默认 x0，墨迹宽 12–13 列、字不要修瘦（L038，用户确认），但“囗”全包围的字（国 因 囤 …）宽 11 列、放在 x1–x11，框内很复杂的（如 國.TC）可撑满 13 列；辶 的统一写法（L039）；竖笔出头与横画位置按思源（L040）；对称字中轴 x6；平行横画等距；只消除糊成一团的黑块（L042）；笔画 1 像素。

不要为了“显得改过”而改；也不要为了复用或贴近圆石而牺牲可读性或地区写法。

## 步骤

1. `WF context --batch BATCH --token TOKEN`：查看进度。恢复任务时保留已保存的字和已完成的复看，只做未完成的部分。
2. 读 KIT/LESSONS.md 和 `KIT/batches/BATCH/inputs.txt`，并**实际查看** context 列出的全部 input 和 example 图片（detail=original）。文件存在不等于看过。
3. 逐字修，每完成至多 10 字就写一个增量文件（如 `KIT/work/BATCH/delta-001.json`）并运行 `WF checkpoint --batch BATCH --token TOKEN --file 文件路径`。格式严格如下：

   ```json
   {"glyphs": [{"id": "U+5B57.SC", "changes": {"4": "#############"}, "note": "", "tumbled": "借鉴", "reuse": ["宀←U+5B87.SC"]}]}
   ```

   - `changes`：键为 0–12 的行号字符串，值为该行完整的 13 个 `.` / `#`；**始终相对 inputs.txt 里的“当前”版本**（第二轮也是）；不改就写 `{}`，但必须列出该字。
   - `tumbled`：`借鉴` / `部分借鉴` / `未借鉴`（圆石没有此字时写 `未借鉴`）。
   - `reuse`：逐像素复用的已通过部件，如 `宀←U+5B87.SC`；没有就省略或写 `[]`。
   - `note`：仍存在的具体问题，或偏离参考 / 范例的原因，一般不超过 60 字；没有就写空字符串。
4. 全部字保存后运行 `WF render --batch BATCH --token TOKEN`，**实际查看**返回的每一页（思源参考 | 圆石 | 修前 | 修后，含 1:1）。
5. 看完运行 `WF viewed --batch BATCH --token TOKEN --render-id 返回的ID --pages 1 2 …`（列出全部页号）。需要时做第二轮：再 checkpoint、render、看图、viewed。每字最多两轮视觉复看。
6. `WF submit --batch BATCH --token TOKEN`。提交只是模型草稿完成，不代表用户接受；结果不会自动进入字体。

遇到 stale token 立即停止写入并汇报。不读取其他批次或别处的历史答案，不浏览网络，不另写渲染器，不使用图像生成模型，不修改 KIT 以外的任何文件（尤其是仓库的 glyphs/、forms/）。

最终只汇报一行：`batch=BATCH; submitted=N; changed=M; concerns=具体问题/无; result=路径`。
