# 源文件格式

字体的全部源数据都是 UTF-8 纯文本，便于直接编辑和用 git 比较。`tools/build.py` 只读这些文件。

## 目录

| 路径 | 内容 | 入库 |
|---|---|---|
| `glyphs/<分组>/<页>xx.txt` | 字形。页 = 码位 ÷ 256（十六进制两位或以上），如 `glyphs/SC/4Exx.txt` 存 U+4E00–U+4EFF | 是 |
| `forms/forms.txt` | 部件形态库 | 是 |
| `build-data/narrow-width.txt` | 各地区思源黑体中画成半角 / 比例宽的码位 | 是 |
| `build-data/constants.txt` | 从参考字体量出的常数 | 是 |
| `build-data/coverage/` `build-data/coverage-required.txt` | 字表与必须覆盖的字表清单 | 是 |
| `history/ai-originals/<分组>/<页>xx.txt` | 像素被改过的字的 AI 原稿 | 是 |
| `tools/editor/data/` | 编辑器用的资料：字母家族、西文参考参数、跨地区部件对照 | 是 |
| `reference-fonts/` | 参考字体（思源黑体等） | 否，见 [reference-fonts.md](reference-fonts.md) |
| `build/` | 构建产物 | 否 |

## 分组与字格

| 分组 | 点阵 | 在字格中的位置 | 内容 |
|---|---|---|---|
| `SC` `TC` `JP` `KR` | 13×13 | 放在 14×14 字格的 x=1–13、y=0–12：左边和底部各留 1 格；底边在基线下 2 像素 | 汉字、假名、注音、韩文、全角符号 |
| `HW` | 7×14 | 整个字格；第 0–10 行在基线以上，第 11–13 行是降部 | 等宽版的西文字母、数字、标点，半角假名 |
| `PR` | 宽 × 14 | 同 HW，宽度可变 | 比例版的西文、泰文、阿拉伯文 |
| `GEOMETRIC-FULL` | 14×14 | 整个字格，不留边 | 制表符、方块元素、盲文、Powerline 的全宽版（比例版只用其中的制表符和方块元素） |
| `GEOMETRIC-HALF` | 7×14 | 整个字格，不留边 | 同上的半宽版（等宽版全用它；比例版用其中的盲文和 Powerline） |
| `HW-L` `PR-L` `GEOMETRIC-FULL-L` `GEOMETRIC-HALF-L` | 同上，高 18 | 14 Large（大号版）用：第 0–13 行在基线以上，第 14–17 行是降部 | 大号版的西文和其他非汉字、18 行的几何字符（2026-10-01）；没有的码位用小号字形 |

字形 ID 写作 `U+XXXX.分组`，如 `U+9AA8.JP`、`U+00E9.PR`。

## 字形块

每个字一段，段与段之间空一行，按码位排序：

```
U+00E9 é adv=7
approved
.......
..#....
（共 14 行）
@ mv:base e 4a4cd6ddf7fa435b906eb52088b375f2 1,5
@ mv:mark:0 ´ 37b1037f7eee4a58a5cc75f4535f8924 3,2
# AI: AI 画这个字时留的说明
# 人工: 人工修改说明
```

1. **首行**：码位、字符（不可见或组合字符写 `-`），分组 HW / PR / GEOMETRIC 还有宽度：
   - `adv=N`：步进 N 像素。
   - `x=N`：水平偏移，只用于步进为 0 的组合符号（泰文上下元音、阿拉伯文附加符号）。
   - `adv=auto`：步进 = 墨迹宽度 + 1，墨迹从第 0 列起；构建时裁掉墨迹以外的空列。比例版西文字母都用它。
2. **第二行：状态**。单独一行，改状态时 diff 只动这一行。
3. **点阵**：`#` 黑、`.` 白，从上到下。
4. **部件关联**（可无），一行一个：`@ 位置 部件 形态ID`，可移动形态再加 `x,y`（形态左上角在本字中的坐标）。
   - 位置：汉字是 IDS 结构里的路径，如 `0`、`1/0`；西文是 `mv:base`（基字）和 `mv:mark:0`、`mv:mark:1`（第几个变音符）。
   - 关联只说明"这些黑点来自哪个形态"。形态的黑点必须都是本字的黑点，关联本身不改变任何像素。
5. **说明**（可无）：`# AI: …` 是 AI 画字时留的问题说明；`# 人工: …` 是人工或脚本写的修改说明。

### 别名

某地区的字与另一个字形完全相同时，只写一行，不重复存点阵：

```
U+3001 、 = U+3001.SC
```

别名只能指向有自己点阵的字。别名来自两处：最初的去重（两个地区的思源黑体在两个字重下轮廓完全相同），以及同字各地区从母版派生后像素与母版完全相同的（见 [design-rules.md](design-rules.md) 第 2 节）。编辑器可以拆开别名，也可以把像素相同的同字字形改为别名。

### 状态

| 值 | 含义 | 由谁写入 |
|---|---|---|
| `approved` | 人工审核通过 | 编辑器“审核通过” |
| `edited` | 人手改过点阵，尚未通过 | 编辑器保存；修改部件形态后所有关联字也变成这个状态 |
| `derived` | 脚本连带改的，尚未通过 | `tools/western/` 的脚本 |
| `ai` | AI 修的版本，可能经过多轮（只加了部件关联、点阵没动的也算） | 最初导入；AI 再修一轮后导入 |
| `draft` | 新增字的底稿：从参考字体点阵化（相位底稿），还没经 AI 或人工修 | `tools/airepair/add_glyphs.py` |
| `hangul-ai` | AI 逐字修的韩文音节 | 最初导入 |
| `hangul-composed` | 程序用字母拼成的韩文音节 | 最初导入 |
| `generated` | 程序按规则生成（制表符、方块元素、盲文、Powerline） | 最初导入 |

状态怎么变：

- 审核通过 → `approved`。
- 导入 AI 再修的版本（只替换 `ai` 状态的字）→ 仍为 `ai`，第一轮版本存入 `history/ai-originals/`。
- 人手改了像素 → `edited`；脚本改了像素 → `derived`。
- 只改说明或部件关联、像素不变 → 状态不变。
- 撤回已通过字的审核、像素不变 → `edited`。
- 修改已通过的字就会失去通过状态，需要重新审核。

## 部件形态库 `forms/forms.txt`

```
FORM c5114278701d476db67b135184384770 fixed 艹 SC 艹 · 上 12×3 @0,0
...#....#....
############.
（共 13 行）
# 自动分割（ids-mask-v1）：BabelStone IDS 结构，边界由本字黑点推断，未人审。
```

首行：`FORM 形态ID 类型 部件 地区 名称`（名称可含空格，占到行尾）。之后是点阵和说明。

- `fixed`（固定形态）：汉字部件，13×13，黑点坐标就是它在字里的坐标，所有关联字中位置相同。
- `movable`（可移动形态）：西文基字和变音符，只存裁到墨迹的小点阵，每个关联字在字形块的 `x,y` 里记自己的位置。
- 形态只拥有黑点，白格全透明：关联字可以在白格里自由加点，但不能删掉形态的黑点。
- 地区 `HW` / `PR` 是等宽 / 比例版西文基字，`WEST` 是两版共用的变音符。
- 形态被修改时，所有关联字在各自位置同步更新。最后一个关联被解除时，形态从库中删除（git 历史里仍在）。
- 汉字形态最初按 [BabelStone IDS](https://www.babelstone.co.uk/CJK/IDS.TXT) 结构从每个字的黑点自动分割（`ids-mask-v1`），只关联最外层能分出的部件，每个黑点最多属于一个形态。分割是推断，没有逐个人审。

## `history/ai-originals/`

格式与 `glyphs/` 相同，状态都是 `ai`，只收录现在像素已不同于 AI 原稿的字。编辑器第一次改动某个 `ai` / `hangul-ai` 字的像素时，会自动把原稿存进这里。编辑器用它显示“AI 原稿”；`tools/western/` 的脚本用它判断哪些地方被改过。

## `build-data/`

- `narrow-width.txt`：每行一个地区，后接十六进制码位或范围。这些码位在该地区思源黑体中的步进 ≤ 700/1000（半角或比例宽），比例版里改用西文比例字形（如日文的 “ ”、韩文的 · ¡ ®）。由思源黑体 2.004 量出，见 [reference-fonts.md](reference-fonts.md)。
- `constants.txt`：`space_advance_proportional`，比例版空格宽度，由 Source Sans 3 的空格步进按 13/1000 缩放、至少 3 像素算出。
- `coverage/`：字表，每行一个码位、范围 `XXXX..YYYY` 或直接写字符，`#` 开头为注释（含来源）。取自同作者的 fontpixel 项目。
- `coverage-required.txt`：8 个字体都必须 100% 覆盖的字表，`tools/verify.py` 检查。

## 编辑器数据 `tools/editor/data/`

- `families.txt`：HW / PR 字母家族。一个家族是一个基字及以它为基础的所有字母（A À Á Â …），记录基字和可分离的变音符。编辑器据此列出西文字母的部件，`tools/western/` 据此做连带更新。
- `reference-western.txt`：每个 HW / PR 字形的参考字体、底稿字号和底稿最左墨迹列，用来叠加参考轮廓。
- `cross-region.json`：思源黑体中各部件在简 / 繁 / 日之间是否写法相同，用于跨地区借用部件时给出提示。
