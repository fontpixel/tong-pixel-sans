# 字形来历

本项目在 2026 年 9 月由一组“修字准备包”逐步做成，2026-09-28 转换为本仓库的纯文本结构。旧包的代码、说明、提示词和学习报告原样存档在 [`archive/`](../archive/README.md)；大块数据（底稿、参考图、每批结果、编辑器修订历史）没有存档，最终结果都已在 `glyphs/` 和 `history/ai-originals/` 里。

## 做法概要

1. **点阵化底稿**：用 WorkBench（FreeType 单色渲染）把思源黑体等字体渲染成点阵，西文和全角符号另做亚像素相位搜索。
2. **去重**：两个地区的思源黑体在 w320、w400 两个字重下轮廓完全相同，才共用一个任务（别名）。
3. **AI 修字**：每批最多 50 字，一个独立会话修一批。输入是参考图、底稿图和精确点阵文本，输出只写改动行，由固定脚本校验、渲染。模型要实际查看修后图，每字最多两轮。模型主要是 `gpt-6-astra`，推理强度 xhigh。
4. **人工审核**：在修字编辑器里逐字修改、审核；AI 定期分析人工改动，总结候选规律和可复用部件，供后续批次参考。
5. **程序生成**：韩文非常用音节由字母拼合；制表符、方块元素、盲文按规则生成。
6. **合并导出**：按地区合并成 8 个 BDF。

## 转换的验证

- 用旧导出脚本重新导出的 8 个 BDF，与 `tools/build.py` 从新结构生成的 8 个 BDF 用 `cmp` 比较，完全相同。
- 旧编辑器中保存过的 6,095 个字形都在新结构中有自己的点阵；点阵、状态、10,358 条部件关联（含位置）、902 条人工说明逐项一致；其余 29,050 个字形的点阵和 6,665 个形态也逐项一致。转换与校验脚本见 `archive/tong-export/migrate_to_repo.py`、`verify_repo.py`、`migrate_extras.py`。

## 旧编辑器的状态怎样映射到新状态

旧编辑器每个字有完整的修订历史（谁在何时保存、是否通过、来源是人还是脚本）。转换时只保留结论：

- 当前版本审核通过 → `approved`。
- 点阵与 AI 原稿相同 → `ai`（包括只加了部件关联的）。
- 点阵不同：最后一次改像素的修订来自脚本（来源记为 program，或说明是脚本的固定文字）→ `derived`，否则 → `edited`。
- 韩文拼合音节若在编辑器里没改过 → `hangul-ai` / `hangul-composed`；几何字符 → `generated`。

从此以后，修改历史由 git 记录。
